# 数据与估值说明

[返回 README](../README.md)

FundBar 将已公布净值与盘中估值分别展示。已公布净值来自基金数据接口；盘中估值由应用根据已披露重仓股和股票行情计算。

## 估值方法

应用读取最新可获取季报的前十大重仓股，先算出这些股票当天的加权平均涨跌，再按基金的股票仓位折算到整只基金：

```text
重仓股涨跌幅 = Σ（重仓股占净值比例 × 股票涨跌幅）÷ Σ（重仓股占净值比例）
估值涨跌幅   = 重仓股涨跌幅 × 股票仓位 ÷ 100
估算净值     = 最新已公布单位净值 ×（1 + 估值涨跌幅 ÷ 100）
```

求和仅包含有行情且权重大于零的股票。参与估算的股票占净资产比例之和称为「覆盖率」；不足 **20%** 时默认不显示盘中估值。设置里打开「低覆盖也显示估值」后，这类基金也会显示估算，并在净值行与小窗里注明覆盖率。

第二步按股票仓位折算，是因为前十大重仓股只代表基金的股票部分，基金其余的债券与现金不会跟着股票涨：一只股票仓位 35% 的基金，重仓股平均涨 1%，基金净值大约只涨 0.35%。股票仓位缺失或不在合理范围时，应用保留第一步的结果。

这一方法假设未覆盖资产与已覆盖重仓股走势相近。季报披露存在滞后，基金调仓、现金、债券和未披露持仓都可能导致偏差；覆盖率也不能直接代表估值精度。ETF 联接、QDII 等基金可能缺少足够的可估算持仓。

## 组合透视

「组合透视」把持有分组里各基金季报披露的持仓按当前市值加在一起，回答「这些基金合起来到底持有什么」。每只基金的权重是它的持仓市值除以组合总市值；组合市值按各基金当前使用的净值（盘中估算或最新公布净值）计算。

- **行业分布**：每只基金的行业占净值比例乘以其组合权重，再按行业名称相加。
- **重仓股穿透**：前十大重仓股以同样的方式加总，得到每只股票占整个组合的比例；同一只股票被多只基金持有时合并，并注明基金数。股票以代码区分，季报未给代码时以名称代替。
- **基金重合度**：两两比较各基金的前十大重仓股，对共同持有的股票取两只基金中较小的占净值比例，加总后即为这对基金的重合度。

这些比例合计通常低于 100%：季报只披露前十大重仓股和主要行业，现金、债券、未披露的持仓以及季报之后的调仓都不在其中。行业名称沿用季报的写法：A 股部分按证监会的行业分类，港股部分按另一套分类，因此同一行业可能以两个名称出现，例如「金融业」与「金融」。重合度只比较季报披露的前十大重仓股，不是两只基金全部持仓的比较。

组合透视是会话状态，切换分组、选择基金或重新打开应用都会回到基金详情；它不会写入本地文件，也不产生新的网络请求。

## 基金对比

走势图右上角的「对比」把最多三只其他关注基金画在同一张图上。每只基金都从所选基金窗口的起点开始，按自己的第一个净值日归一化：较年轻的基金从它成立后的第一个净值日开始，起点为 0%。曲线按前复权净值计算，分红或拆分不会在曲线上形成下跌的缺口。纵轴是同一根百分比轴，0% 为基准线；风险指标、历史净值列表和周期选择仍只描述所选基金。对比是会话状态，不写入本地文件，切换或移除基金时自动退出对比。

## 分享图

主窗口顶部的「分享」菜单或菜单栏图标的右键菜单「分享今日收益」，可以复制或保存一张 720 DIP 宽（2 倍像素）的深色分享图：顶部是「基金估值」与数字所属的日期、盘中估算或已公布净值，中间是持有分组当日的涨跌幅，下面按列表顺序最多列出十只基金的涨跌（其余以「另有 N 只」注明），底部注明估值仅供参考。默认图片不含任何金额；「含金额」版本才加上今日收益和每只持有基金的收益，仅关注、未持有的基金始终不显示金额。分享图在应用内离屏绘制，不是窗口截图。

## 显示规则

- 股票行情日期晚于最新已公布净值日期，且覆盖率满足要求（默认 20%，或在设置里允许低覆盖）时，使用估值。
- 当日净值公布并被应用获取后，切换为已公布净值。
- 基金数据脚本每日晚间生成一次，可能晚于当日净值公布。最新一日净值缺失时，应用改从净值列表接口读取，避免把前一交易日的涨跌当作当日。
- 无可用估值时，显示最新已公布净值；周末、节假日或行情尚未更新时，应结合界面的日期与状态阅读数值。

应用同时保留一份估值准确度记录：行情日的收盘估值在当天 16:15（港股也已收盘）之后才算最终值，行情日期已经过去的次日同样如此；应用把这些最终估值与覆盖率记入 `estimates.json`，盘中仍在变动的估值不记录，应用没有在收盘后运行的日子也不会有记录。基金随后公布该日净值时，应用用当日真实涨跌幅补全这条记录（分红日按公布涨跌幅，而非单位净值之比）。「重仓股」标题旁的「估值偏差」取最近最多 20 个已公布的交易日，显示收盘估值与当晚公布净值的平均绝对差；不足 3 个时只显示「估值偏差记录中」。偏差越小，盘中估值越可信。每只基金最多保留最近 60 条记录。

持仓市值根据当前持有的份额与当前使用的净值计算。累计收益在手动录入时按份额与成本价估算；记下每笔交易后，它包含未卖出份额的持有收益、已卖出部分的已实现收益和现金分红，并把手续费计入成本。两种方式都只是估算，不能替代账户账单。

## 交易记录与成本

在「我的持仓」里可以只填份额与成本价，也可以记下每笔交易，让份额与成本自动计算。

- **加权平均成本**：买入把成交金额和手续费一起计入成本，成本价是总成本除以总份额。卖出按比例带走对应的成本，不改变成本价。
- **手续费**：买入和卖出的手续费计入成本，或从卖出到账金额中扣除，并计入累计投入。
- **现金分红**：计入收益，不改变份额和成本。
- **红利再投**：按零成本增加份额；份额折算也用同一种记录。
- **同日顺序**：同一天的多笔交易按「分红 → 红利再投 → 卖出 → 买入」重放，与录入先后无关。
- **收益率**：累计收益率 = 累计收益 ÷ 累计投入；持有收益率是当前市值相对加权平均成本的变化，止盈 / 止损提醒看的是持有收益率。
- **保存位置**：交易记录保存在 `ledger/<基金代码>.json`，与 `funds.json` 里的份额、成本互为镜像；只填两个数字的手动方式仍然可用。

交易记录文件损坏时，应用会把它另存为 `<基金代码>.json.bad`，并显示上次保存的份额与成本。移出自选、删除分组或改回手动录入时，交易记录不会直接删除，而是另存为 `ledger/<基金代码>.json.removed`（同一只基金只保留最近一份），需要时把文件改回 `.json` 并重新加入该基金即可恢复；改回手动录入和删除单笔交易在卡片里会给出「撤销」，可以当场恢复。

## 提醒规则

系统通知默认关闭，需要在设置的「提醒」中打开。三条规则如下：

- **盘中涨跌提醒**：对所有分组的每只基金，当估值取的是当天行情（行情日期为北京时间当天）且估算涨跌幅的绝对值达到阈值（默认 2%，可调 0.5% 到 20%）时提醒。同一只基金每个交易日最多一次；同一次刷新中达到阈值的多只基金合并为一条通知，超过 3 只时列出涨跌幅最大的 3 只并注明总数。
- **净值公布提醒**：只针对持有分组，每个交易日最多一次，市场休市日不提醒。持有分组当天的净值全部公布时提醒；22:00 后若只公布了一部分，也会提醒并说明还有几只待公布。通知中的收益与涨跌幅与菜单栏一致：有份额时报告当日收益金额和比例，没有份额时报告平均涨跌。
- **止盈 / 止损提醒**：在基金详情的「我的持仓」中为每只持仓基金单独填写，留空即关闭。持有收益率达到止盈线或跌到止损线时提醒：进入区间时提醒一次，停留在区间内不再提醒，隔天也不重复；离开后再次进入会再提醒，但每只基金每个方向每天最多一次。

点击只涉及一只基金的通知会打开该基金的详情；涉及多只基金的通知只打开主窗口。通知的标识记录了该打开哪只基金，因此应用重启后点击此前的通知同样有效。提醒记录保存在 `alerts.json`，重启应用不会重复发送当天已经发出的内容。若系统没有授予通知权限，设置窗口会显示提示；「发送测试通知」可在不打开任何规则的情况下检查通知是否可达。

## 数据来源

| 数据 | 提供方 | 接口 |
| --- | --- | --- |
| 基金名称、历史净值与股票仓位 | 天天基金 / 东方财富 | `fund.eastmoney.com/pingzhongdata/{code}.js` |
| 最新一日净值（数据脚本未更新时） | 天天基金 / 东方财富 | `api.fund.eastmoney.com/f10/lsjz` |
| 季报前十大重仓股与占净值比例 | 天天基金 / 东方财富 | `fundf10.eastmoney.com/FundArchivesDatas.aspx?type=jjcc` |
| 基金行业配置 | 天天基金 / 东方财富 | `api.fund.eastmoney.com/f10/HYPZ/` |
| 个股行业与概念 | 东方财富 | `push2.eastmoney.com/api/qt/ulist.np/get` |
| A 股、港股行情 | 腾讯财经 | `qt.gtimg.cn/q=...` |
| 上证、沪深300 与创业板指数 | 腾讯财经 | `qt.gtimg.cn/q=...`（与股票行情同一请求） |
| 基金搜索 | 天天基金 / 东方财富 | `fundsuggest.eastmoney.com/FundSearch/api/FundSearchAPI.ashx` |

大盘指数在菜单栏小窗顶部随当日摘要显示，可在设置的「通用 → 小窗显示大盘指数」关闭；指数只保存在内存中，不写入基金的缓存文件。

当前接入无需配置 API Key。接口可用性与字段由提供方决定，发生变更时可能影响数据更新。项目代码的 MIT 许可不授予第三方数据使用权，使用数据时应遵守提供方条款。

## 刷新与缓存

| 内容 | 当前策略 |
| --- | --- |
| 股票行情 | 交易时段约每分钟刷新，其余时间约每 15 分钟刷新 |
| 基金档案与持仓 | 满足新鲜度条件时复用 20 分钟内的缓存 |
| 最新一日净值 | 数据脚本缺当日净值时读取，每只基金每 30 分钟最多一次 |
| 行情请求 | 合并自选基金的股票代码，每批最多 60 只 |
| 应用启动 | 优先读取本地缓存，再请求更新 |

调度按北京时间与交易日判断：周末与法定节假日（A 股休市日）不进入交易时段刷新。交易日历表覆盖 2026、2027 年的 A 股休市日；表未覆盖的年份按工作日判断，即周一至周五视为交易日。网络请求耗时可能影响实际刷新间隔；数据对应日期应以界面显示为准。

数据适配逻辑见 [`internal/source`](../internal/source/source.go)，估值算法见 [`internal/model`](../internal/model/model.go)，显示与刷新逻辑见 [`internal/app`](../internal/app/app.go)。
